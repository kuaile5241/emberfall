## 对现有项目的判断

现有项目已经能完成整备、战斗、局内构筑和回营，但再次出征的长期理由偏弱。玩家看到相同的六区路线，装备收藏和营地三次强化也很快接近上限。多放怪、多换颜色、再加几段介绍文字，不能单独解决这个问题。

建议保留“营地 → 出征 → 选择 → 结算 → 新目标”的清晰结构，先把出征目的做成实际状态：玩家知道为什么进副本、当前要完成什么、成功带来什么新内容、失败后还有什么进展。剧情通过短任务和可回看的记录落地，不在清怪中反复弹长文本。

开放世界可以成为后续方向；现阶段先做可选副本网络，更适合当前连续地图、俯视战斗与浏览器存档架构。地图扩大以后还要处理空地密度、导航、碰撞、加载、存档和任务依赖，不能把“大地图”当成玩法完成度。

## v0.7 的建议交付边界

这是一轮可验收的产品化里程碑，不能据此宣称已经是完整正式版。建议围绕一个可闭环的故事线实现：

1. **营地有下一目标。** 原创主线交代钟下墓城与营地的关系；任务日志记录进度、线索、已完成目标和下一步。已读内容可回看，重复出征不强迫重读。
2. **副本选择真的影响玩法。** 至少新增一个具有不同遭遇规则的可玩副本。若沿用原场景骨架，界面明确它属于变体 / 挑战，不冒称全新地图。新区域最好同时改变关键地标、通行结构、敌人组合、环境危险和 Boss 行为；只有灯光、名字或血量变化不算新的完整章节。
3. **成功推进主线，失败仍有可读结果。** 首通推进剧情、解锁下一目标；回刷可以获取常规收益，但首通报酬只发一次。死亡、撤退、刷新后的旧出征结算均有明确规则。
4. **目标与选择贯穿一局。** 战斗 HUD、奖励和结算显示实际副本、目标和取得的线索。支路可承担风险换收益或调查线索，而不是只有无条件领钱。
5. **数据可扩展并保护旧存档。** 副本、剧情、任务、首通和奖励由稳定 id 定义；进度版本迁移、有幂等结算，界面与双语文字取同一份状态。

建议首通剧情以“调查灾变原因 → 取回线索 → 定位下一威胁”推进。每个目标需要一个战斗或探索动作作证，不能仅靠点完对话解锁全部内容。以上是原创设计方向，最终角色、关卡和数值以本轮实施计划及代码为准。

## 本轮选定的实现范围

v0.7 沿用第一章“钟下墓城”的六区，加入遗物名册与铸钟铭印两个可调查物证，用四个剧情节点串联守夜人、档案员和铁匠。铸印需要清理工坊并靠近后持续互动；击败丧钟守卫且领取前置剧情奖励，才开放下层水道。

第二张地图在代码中命名为“沉钟水道”，包括雨落蓄池、断桥闸室、沉钟穹室三个区域。它使用向左转折的独立地图与通行图，加入水压预警、需要持续开启的闸轮，以及幽潮守望者的潮环 / 涌浪攻击；闸轮把该局 Boss 的伤害降低 20%。这是一张有独立通行结构和机制的新副本，不将换色场景拆称三个新章节。

水道三个剧情节点收束这段调查线，剧情证据和一次性奖励保存在营地中。局内调查物证与普通补给分开统计，剧情报酬只领一次，通关与探索记录可以回看。上述范围对应本轮实现契约；最终画面、浏览器接线与发布状态应以版本验收文档为准。

新增 `tests/campaign-flow.test.js` 与 `tools/campaign-bot.mjs`。第一次独立运行四项检查通过：三元素使用不同种子，以正常属性输入机器人连续完成两张地图、取回所有相关物证、顺序领取七个剧情节点、重载存档，并验证结算 / 剧情领奖不能重复加收益。第一章各 293 击杀，水道各 116 击杀。机器人只输出正常玩家动作，精确读取敌人与预警，不改变生命、伤害、坐标、敌人列表或生成规则；这些时间与结果不能代表真人难度、视觉或性能验收。

## 本项目 v1 的产品标准

以下是项目建议验收标准，不是行业认证，也不是来自参考游戏的硬性规则。

- **故事与终点：** 新存档能自然理解目标，完成一个有起因、变化和结果的故事弧；完整结局可达，任务日志可回看，跳过叙事仍能玩。
- **内容差异：** 主线副本通过地理 / 地标、遭遇、环境危险、Boss 或探索目标区分；不能把同一路线的不同配色计入独立关卡数量。
- **重复游玩：** 三元素各有不止一种有意义的构筑；路线或遭遇提供选择；通关后可选挑战增加规则与奖励，避免单纯堆生命。
- **成长经济：** 普通出征、失败和首通的收益透明；永久成长有终点；资源有去处；没有重复领奖、负库存、无限消费或重复保存漏洞。
- **存档可靠：** 旧版本可迁移；关闭与刷新可恢复约定的进度；损坏存档有可理解的恢复方式；导出备份可以导入。是否提供云存档另外决定。
- **上手与可访问：** 教学可重看、输入能修改；重要信息不只靠颜色；字幕和中英文界面完整；设置不导致战斗 / UI 状态不同步。
- **质量证据：** 新建存档、正常升级存档、死亡、撤退、首通、重复通关和设置切换都有测试；正常属性机器人只用于流程验证，还需记录真人体验与性能设备矩阵。
- **发行可用：** 外部用户能按说明启动或访问发布版，仓库与素材许可清晰；README 说明实际支持的平台、保存范围、问题反馈方式和已知限制。

测试和内容数量只是必要证据的一部分。没有真人体验或设备表现数据时，不得写“难度平衡已经完成”“所有设备流畅”“已达到商业 ARPG 规模”。

## 本轮验收建议

| 路径 | 要核对的结果 |
| --- | --- |
| 新建存档 → 读主线 → 整备 → 出征 → 完成目标 → 结算 → 下一目标 | 主线、解锁、界面和实际战斗一致 |
| v0.6.1 存档升级 | 原金币、装备、补给与营地等级保留；新增进度合理初始化 |
| 同一副本第二次通关、双击结算、跨页旧状态 | 常规收益按本局结算，首通奖励与剧情不重复 |
| 死亡 / 撤退 / 刷新后旧出征结算 | 不虚报首通，不错误解锁，不吞掉旧战利品 |
| 中文 ↔ English、暂停 / 选卡 / 换装 | 显示同一任务状态，不重开局，不再出现领奖后移动失效 |
| 新副本完整正常属性流程 | 不通过改血量、伤害或移除敌人来制造通过结果 |

代码测试、浏览器流程、真人难度、视觉观感与长期性能分别报告。保存文件 / 构建成功 / 推送 GitHub 都不能替代玩法验收。

## 资料边界

三款参考游戏的玩法事实均来自其开发商官网或官方 press kit；没有使用玩家 wiki、付费媒体评价或搜索摘要作最终事实。宣传页表述按开发者自述记录，历史补丁按当时版本记录。它们帮助选择机制，不证明照搬机制就能提高留存或销量。

本次没有获得 Emberfall 玩家留存、平均死亡点、完整真人游玩时长、各职业长期胜率和跨显卡性能数据。正式版范围、平衡、平台与发布方式仍需在后续里程碑持续验证。
