# Emberfall 产品化计划

截至 2026-10-01。本计划参考 [玩法调研与主张对账](product-research-v0.7.md)，机制选择属于本项目的设计判断。

目标：单人、桌面浏览器、可完整通关并反复构筑的 3D 动作肉鸽。保留可爱角色、暗色营地、火雷水 AOE。公开 MIT 源码，不把当前版本称为正式完整产品。

## 本轮实施清单

1. 玩法定义：第一章保留墓城六区，守墓遗物与铸钟铭印解释钟声来源；主线进度和旧委托独立。第二章沉钟水道有新坐标、新通道、新地标、三区、闸轮和幽潮守望者，不以换色充当新地图。
2. `src/campaign.js`：数据化七段主线、前置、奖励、章节元数据；`src/profile.js`：V4 加字段兼容、有效物证合并、固定出征身份、幂等结算和领奖。坏档和并发冲突不自动覆盖。
3. `src/world.js` / `src/game.js`：每局地图实例共享碰撞、导航、几何；移除固定第六区 Boss 判断；水压定点预警；潮汐内圈安全区；闸轮持续操作可中断。
4. `src/environment.js` / `src/view.js`：按地图重建场景；灰蓝水道、连拱与闸轮地标；释放生成资源；防止重复点光、角色和动态对象积累。
5. `src/camp-ui.js` / `src/campaign-ui.js` / `src/main.js`：章节选择、锁定原因、剧情纪事、当前主线、持续操作进度；中英文运行时切换。
6. 验证修复：保留原六区测试；新增剧情存档与两图输入流程；真实浏览器自动点击营地、领奖、切图与换语言。测试用独立键，不动玩家存档。
7. 验收记录：保存测试报告、真实截图、已知限制；README 与实际范围一致。
8. 上传：中文提交 → develop → 发布分支 → main → 同步 develop；核验 GitHub 主分支、分支差异和工作区。未授权公开站点部署。

## 风险和回退

- 地图/碰撞不一致：同一世界定义供模拟、渲染和小地图；不同地图都验输入步行，不能只用坐标传送验收。
- 存档字段丢失或串局：固定 pendingRun.expeditionId，按该身份过滤证据；新字段补默认，旧奖励不重复。
- 任务卡住：物证可跨局保存，未搜齐仍能结算；阶段奖励在营地顺序领取，不强制重复通关。
- 切图资源泄漏：多次往返切图检查环境灯和动态对象数量；共有模型和材质不错误释放。
- 自动化不代表真人体验：机器人有完整战场信息；仅用于功能和可达性验收，不据此宣称难度平衡或帧率达标。
- 回退：用 Git revert 撤销本次发布，保留 V4 原存储键和旧字段。新增剧情数据不影响旧版本读取核心经济，回退版本不会继续推进新主线。

每个后续里程碑都按“玩法 → 实现 → 验证修复 → 验收 → GitHub”交付。发行版本必须达到表中 v1.0 条件，而不是只增加关卡数量。
