# v0.4.1 奖励后键盘失效修复

## 范围与证据

- 对象：本地《余烬地牢》v0.4.0，2026-10-01；用户反馈领取奖励后无法移动。
- 现场正式页面仍加载 `index-PvHYBszf.js`。在实际 keydown 处理器暂停检查，游戏 status=playing、界面 overlay=pause（自动暂停），但选牌锁为 true；30 击杀、103 金币、150/150 生命保留。
- 新页面独立 `?qa=1` 验证，未重置用户营地、设置和战绩。

## 事实与根因

| 项目 | 结论 |
|---|---|
| 实际发生了什么 | 最后一张祝福确认成功后无法响应 WASD、E、K、Esc 等键盘输入；模拟与鼠标按钮本身没有永久停止。 |
| 原先声明了什么 | v0.4 声明卡牌选择及实际流程已验证；当时只核对奖励生效，没有在领奖后断言真实键盘输入产生位移。 |
| 现有规则及是否执行 | 已有“实现完成后验证当前行为”的要求，但本次验收粒度不足，未覆盖 UI 输入锁与引擎恢复之间的连接。 |
| 执行违规或规则缺口 | 验收执行缺口；65 项旧测试主要覆盖引擎与存档，不能替代主界面 keydown→frame→Game 的验证。 |
| 根因 | `chooseUpgrade` 在 200ms 选择动画开始设 `blessingSelectionPending=true`，成功回调未释放；最后一张后不会再调用 `showUpgrade` 重置，顶层 keydown guard 永久 return。 |

## 修正与验证

| 项目 | 结果 |
|---|---|
| 已修复 | 选择完成时 finally 释放锁；键盘防重入仅作用于祝福界面；动画期间打开暂停后，回调不再自动关闭暂停。旧局回调也不会清除新局的选择锁。 |
| 权威落点 | `src/main.js`；未修改 AGENTS 或长期记忆。 |
| 检查器与真实失败样例 | 新增 `tests/reward-input.test.js` 6 项，读取实际 main.js 事件/帧循环和真实 Game，仅 stub 浏览器外围。临时还原旧函数及 guard 后 6 项全部失败；修复后全部通过。 |
| 自动验证 | `npm test` 71/71；`npm run build` 成功，版本 0.4.1，入口 `index-p30YmvJf.js`，仅保留既有包体提示。 |
| 浏览器验证 | 正式包中通过 E 打开奖励、实际点选卡牌、K 施法及 Esc 暂停；通过 DOM 键盘事件保持 W 20 帧，位置由 (0,10) 变为 (-0.898366,8.596376)，移动约1.6665米，status=playing、overlay=null。瞬时 native keypress 本身不足一帧，不误称持续移动验证。 |
| 用户原局恢复 | 使用页面调试器就地解除当前锁，并包装已加载页面的恢复函数，使之后领取同样释放锁。无刷新、重开、改属性或奖励；30击杀、103金币保留。实际 Esc 可暂停。结束时仍暂停供用户继续。永久源码/构建另已修正。 |
| 未解决项与授权边界 | 无本次已确认阻塞残留；没有借此扩展玩法、改存档格式、提交Git或公开发布。 |
