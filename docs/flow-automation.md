# 游戏流程自动化与浏览器演示

日期：2026-10-01，v0.6.1。本轮在本地补上可重复运行的流程检查，并在 Codex App 内置浏览器中演示。用户原页面和原存档保留。本页记录功能验收；Git 提交推送依用户的后续授权单独执行，功能分支为 `codex/bilingual-ui`。

## 重跑方式

在项目目录运行：

```sh
npm run test:flow
npm test
npm run build
```

`test:flow` 执行 86 项流程及相关回归，将终端日志、JUnit 和 JSON 写入 `artifacts/flow-automation/`；`npm test` 执行全部 157 项。命令本身不启动浏览器，JSON 会明确记录 `browser.status=not_run_by_this_command`。

4173 预览服务运行时，打开以下地址会自动执行实际页面流程：

- [中文浏览器流程](http://127.0.0.1:4173/?qa=1&flow=1&seed=913)
- [英文浏览器流程](http://127.0.0.1:4173/?qa=1&flow=1&seed=913&lang=en)
- [放慢营地操作与战斗的可见演示](http://127.0.0.1:4173/?qa=1&flow=1&seed=913&demo=1)

右上角测试面板显示当前步骤和最终 PASSED/FAILED。开发者控制台中的 `window.__emberfallFlow` 保存完整检查项、关卡、战斗结算、最终营地存档和失败状态。

只有同时使用 `qa=1&flow=1` 才加载自动驱动。每次打开或刷新都生成新的 `.qa.flow.UUID` 存档键，角色、补给、设置、战绩与语言均隔离，不删除或覆盖普通存档。刷新会重新测试，并不会续玩上一份测试存档。

## 覆盖范围

浏览器检查依次执行三职业切换、锁定装备查看、领取委托、按真实成本购买两种补给、选择携带、双语切换、正式出征、暂停和画质设置、战场换装、键盘事件移动、六区战斗、祝福选择、领奖后继续移动、高级装备外观、最终 Boss、胜利结算、委托领取、营地强化、再次出征和收队回营。

补给确实扣库存，金币按真实成本和奖励结算，战利品来自实际击杀及清场；没有提高生命、伤害、速度、药水数量，或注入/削弱敌人。角色和高级护甲通过真实 ActorSystem 检查。

逻辑层另有三职业、六个种子的完整正常难度通关、自然死亡、带真实战利品撤退、保存读取失败和跨页冲突回归。死亡按 60%、撤退按 25% 结算；重复结算与重复领取不会再次发奖。这些异常分支由 Node 测试覆盖，不属于本次两个浏览器通关路径。

## 本轮发现与修复

1. 连续排队升级时，在 200ms 选卡动画中暂停、恢复，再点击旧卡，会误消费下一组祝福。恢复后现在保留已选卡并持续禁用旧卡，等这一组提交后再开放下一组。新增中英文、普通/减少动画四项回归，并由浏览器实际页面流程检查。
2. 六区通关后营地 `stats.bestRoom` 仍为 0。浏览器结算报告暴露了战斗摘要遗漏关卡编号；`Game.runSummary` 现在传递从 1 开始的 `room`。通关、死亡、撤退分别保存 6、2、3，后续较短出征不会降低纪录。
3. 流程检查命令遇到子进程信号终止时，退出码不会再错误返回 0。

修复前通关报告保留为 `browser-zh-before-depth-fix.json`、`browser-en-before-depth-fix.json`；深度断言的失败输出保留在同一产物目录。最终结果与截图也保存在该目录。

## 证据边界

浏览器战斗使用固定 30Hz 输入机器人，经过实际 `Game.update → consumeEvents → render → checkpoint`。营地和弹窗由页面按钮的真实监听器处理；键盘检查使用合成 KeyboardEvent，并验证实际位移。Browser Use 另实际点击了军械查看与装备按钮，截图显示法师切为骑士及高级服饰。

因此本轮能证明 DOM、游戏事件、模型渲染与同页存档结算的连通性。机器人知道敌人和攻击预警位置，不能据此认证真人难度、全部原生键鼠输入或实时帧率。本轮浏览器没有验证刷新续局、跨设备、手柄、云存档或长时间性能；不声称所有未知 bug 已清零。
