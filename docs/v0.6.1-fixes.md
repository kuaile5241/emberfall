# v0.6.1：职业换装修复、暗色界面与装备外观

日期：2026-10-01。保留此前双语、圆润建模和营地优化；本次功能验收时尚未提交、合并、推送或公开发布，Git 操作依后续单独授权处理。

## 范围与证据

- 用户反馈「切换都没有用」，随后确认是职业或装备切换，并要求主动测试完整游戏流程。
- 用户当前正常页加载的是 v0.6 构建 `index-Cv5ctnPk.js`，不是旧缓存。正常存档存在 `pendingRun`，三个职业按钮实际 `disabled=true`。修复前只读截图：`artifacts/v0.6.1-qa/before-user-pending.png`。
- 本轮另按用户要求将界面改为暗色，并让高级装备产生真实穿着差异。
- 浏览器流程使用独立 `?qa=1` 与 `.qa` 存档；不刷新或操作用户正常游戏页，不清空正常存档，也不代替用户结算原出征。

## 事实与根因

| 项目 | 结论 |
|---|---|
| 实际发生 | 待结算记录导致营地职业、装备和补给选择同时被禁用，点击没有效果。 |
| 原先证据边界 | v0.6 的营地点击验收使用已结算存档；测试通过不能证明待结算整备正常。旧测试把全部禁用视为预期。 |
| 根因 1 | `ProfileStore._change` 与营地渲染把只改下一局选择的动作，和消费、任务、新出征一起阻断。 |
| 根因 2 | 职业图标固定使用基础武器，已装备高级武器时点同职业会回退。 |
| 根因 3 | 多页保存后内存 `_raw` 过期，写入持续返回 `storage_conflict`，营地缺少读取最新存档的路径。 |
| 根因 4 | 同帧换职业后攻击/施法事件先给旧模型，下次渲染更换模型时动作消失；伤害和冷却已经生效。 |
| 操作歧义 | 军械卡片点击是查看，装备按钮原先在技能和六项属性后方，容易被理解为换装无效。 |

## 修正

- 待结算时可选择下一局职业、已收藏武器和有库存的补给。旧局 `run`、已消耗补给、任务和累计战利品不变；消费、强化、任务领取和再次出征仍需先结算。
- 职业快捷键保留当前同系装备；切至其他职业时优先使用已收藏高级武器。卡片仍可查看，装备按钮移到详情顶部，明确说明「查看 → 装备」。锁定武器只可查看及跳转委托。
- 营地在切回页面和保存前读取最新记录；写入冲突不自动重复消费。战场读取只接受同一 `runId`，不同、缺失、损坏的出征不接管、不覆盖。
- 玩家装备/攻击/技能事件交付前同步当前真实模型；过期武器动作不排队重放。
- 营地、军械、行囊、委托、HUD、暂停/设置、战斗装备和祝福界面统一炭黑、深灰与暖金。营地预览台石料和补光也去掉绿调；世界环境和技能元素色不随此改变。
- 六件武器对应六种服饰名称。基础职业保留原服饰；火、雷、水高级装分别添加重甲冠饰、轻甲兜帽饰件、法师肩领帽冠。是真实 Mesh，安装在头、胸、上臂和前臂骨骼上，营地与战场共用，切换时释放旧配件资源。
- 游侠亮绿布料改为炭蓝灰。兜帽与脸属于同一 Mesh，因此只复制本地几何并重绘原绿色顶点；皮肤、棕色皮革、UV、骨骼权重及共享 GLB 保持原值。

## 边界
